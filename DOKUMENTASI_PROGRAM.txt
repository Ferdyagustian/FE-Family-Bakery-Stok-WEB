================================================================================
1. DESKRIPSI UMUM PROGRAM
================================================================================

Family Bakery - Sistem Manajemen Stok & Point of Sale (POS) WEB adalah aplikasi
web enterprise modern berbasis cloud yang dirancang khusus untuk operasional
usaha roti/bakery. Sistem ini mengintegrasikan katalog master produk, inventaris
multi-cabang (multi-store), kasir penjualan (POS) dengan keranjang belanja,
cetak struk belanja thermal, prediksi penjualan berbasis AI, riwayat aktivitas
(audit trail), serta pelaporan performa bisnis secara terpusat.

Aplikasi dirancang dengan arsitektur multi-cabang adaptif, memisahkan wewenang
pengguna secara ketat antara Admin Utama dan Manager/Kasir Cabang, sehingga
setiap toko cabang dapat beroperasi mandiri saat melayani pembeli namun tetap
terpantau secara langsung dan transparan dari dashboard pusat.

================================================================================
2. TUJUAN PROGRAM
================================================================================

- Digitalisasi menyeluruh dari pencatatan manual/kertas menjadi sistem cloud terintegrasi.
- Sentralisasi katalog produk master yang seragam di seluruh cabang dengan kontrol harga fleksibel.
- Menyediakan modul Kasir (POS) modern dengan keranjang multi-item, beragam metode pembayaran, dan cetak struk thermal.
- Memantau pergerakan stok, omzet penjualan, margin keuntungan, dan performa cabang secara real-time.
- Memberikan peringatan stok menipis otomatis baik di dashboard maupun melalui notifikasi email langsung (Resend API).
- Memanfaatkan kecerdasan buatan (AI TimesFM Engine) untuk meramal kebutuhan produksi 7 hari ke depan.
- Mencatat seluruh riwayat aktivitas sistem (Audit Trail) demi akuntabilitas dan keamanan data.
- Menghasilkan laporan analitik yang siap diekspor ke format Excel (.xlsx).

4. ARSITEKTUR APLIKASI
================================================================================

Aplikasi menerapkan arsitektur Next.js App Router modern yang mengoptimalkan
performa dan keamanan data:

  a) Edge / Middleware Protection (middleware.ts)
     - Memeriksa JWT cookie pada setiap navigasi route.
     - Role-Based Access Control (RBAC): Membatasi peran MANAGER agar hanya dapat
       mengakses cabangnya sendiri (/stores/[id]) dan laporan terkait (/reports).
       Mencegah akses liar ke dashboard pusat, master produk, audit, atau forecast.

  b) Server Components (RSC)
     - Mengambil data langsung dari database Supabase melalui Prisma di sisi server.
     - Penerapan Incremental Static Regeneration (ISR) dengan revalidasi:
       * Dashboard: revalidate 60 detik
       * Detail Cabang: revalidate 30 detik
       * Master Produk: revalidate 30 detik
       * Audit Log: revalidate 0 (selalu real-time)

  c) Server Actions (Mutasi Data Aman)
     - Semua operasi mutasi (Create, Update, Delete, Record Sale, Bulk Restock, Price Adjust)
       dieksekusi melalui Server Actions dengan proteksi otorisasi assertStoreAccess()
       dan otomatis mencatat jejak audit log.

  d) Client Components (Interaktivitas Tingkat Tinggi)
     - Komponen keranjang belanja POS, kalkulator pembayaran, modal struk belanja,
       pencarian produk real-time, filter audit log dinamis, dan chart interaktif.

  e) API Routes
     - /api/auth/logout        : Handler terminasi sesi dan audit log logout.
     - /api/export             : Endpoint pengambil data penjualan dan stok terfilter untuk Excel.
     - /api/upload             : Upload gambar produk ke Supabase Storage.
     - /api/notify-low-stock   : Endpoint cron otomatis terproteksi CRON_SECRET (timing-safe)
                                 untuk mendeteksi stok menipis dan mengirim email via Resend.

6. MODEL DATABASE (SKEMA PRISMA TERKINI)
================================================================================

Aplikasi menggunakan 6 model database relasional yang telah dioptimalkan:

--- 1. Model: User ---
  id           : String (CUID, Primary Key)
  username     : String (Unique)
  passwordHash : String (Terenkripsi bcrypt)
  name         : String? (Nama lengkap tampilan)
  role         : Enum [ADMIN | MANAGER]
  storeId      : String? (Foreign Key ke Store, Cascade Delete)
  createdAt    : DateTime
  Indeks       : [storeId]

--- 2. Model: Store (Cabang Toko) ---
  id            : String (CUID, Primary Key)
  name          : String (Nama cabang, misal: Cabang Sudirman)
  location      : String? (Alamat / lokasi fisik)
  storeProducts : StoreProduct[] (Relasi ke inventaris fisik cabang)
  sales         : Sale[] (Relasi riwayat transaksi cabang)
  users         : User[] (Staf / Manager yang bertugas di cabang)
  createdAt     : DateTime
  updatedAt     : DateTime

--- 3. Model: Product (Katalog Master Produk) ---
  id            : String (CUID, Primary Key)
  name          : String (Nama varian roti / kue)
  description   : String? (Keterangan produk)
  imageUrl      : String? (URL gambar Supabase Storage)
  price         : Float (Harga jual standar)
  discount      : Int (Diskon promo default dalam %, default 0)
  sales         : Sale[] (Relasi ke transaksi penjualan)
  storeProducts : StoreProduct[] (Relasi ke stok per cabang)
  createdAt     : DateTime
  updatedAt     : DateTime

--- 4. Model: StoreProduct (Inventaris Fisik Cabang) ---
  id            : String (CUID, Primary Key)
  storeId       : String (Foreign Key ke Store, Cascade Delete)
  productId     : String (Foreign Key ke Product, Cascade Delete)
  stockQuantity : Int (Jumlah unit fisik yang tersedia, default 0)
  createdAt     : DateTime
  updatedAt     : DateTime
  Relasi Unik   : @@unique([storeId, productId])
  Indeks        : [storeId], [productId], [stockQuantity]

--- 5. Model: Sale (Catatan Transaksi Penjualan) ---
  id            : String (CUID, Primary Key)
  storeId       : String (Foreign Key ke Store, Cascade Delete)
  productId     : String (Foreign Key ke Product, Cascade Delete)
  receiptNo     : String? (Nomor resi unik struk, e.g. FB-20261012-1042)
  paymentMethod : String? (Metode bayar: Tunai | QRIS | Transfer)
  cashPaid      : Float? (Nominal uang tunai diserahkan)
  change        : Float? (Nominal kembalian)
  quantitySold  : Int (Jumlah unit yang terjual)
  totalAmount   : Float (Total harga transaksi setelah diskon)
  profitAmount  : Float (Estimasi nilai keuntungan bersih)
  saleDate      : DateTime (Waktu transaksi tercatat)
  Indeks        : [saleDate], [storeId], [productId], [storeId, saleDate], [receiptNo]

--- 6. Model: AuditLog (Jejak Aktivitas Sistem) ---
  id         : String (CUID, Primary Key)
  userId     : String? (ID pengguna pelaku aksi)
  username   : String? (Username pelaku)
  action     : String (Aksi: LOGIN, LOGOUT, FAILED_LOGIN, CREATE_PRODUCT, dll)
  entityType : String (Tipe objek yang dimanipulasi: Product, Store, User, dll)
  entityId   : String? (ID entitas terkait)
  entityName : String? (Nama objek untuk keterbacaan UI)
  detail     : String? (Data rinci payload dalam format JSON)
  storeId    : String? (Cabang tempat aktivitas terjadi)
  createdAt  : DateTime (Timestamp waktu kejadian)
  Indeks     : [userId], [action], [storeId], [createdAt], [entityType, entityId]

7. FITUR-FITUR PROGRAM TERKINI (YANG SUDAH ADA & AKTIF)
================================================================================

7.1 AUTENTIKASI, SESI & PROTEKSI KEAMANAN
    - Autentikasi berbasis username dan password dengan enkripsi bcrypt.
    - Perlindungan Brute-Force: Maksimal 5 kali percobaan login gagal dalam 15 menit
      akan otomatis memblokir login sementara (TooManyRequests).
    - Seluruh percobaan login berhasil dan gagal dicatat ke dalam AuditLog.
    - Sesi berbasis token JWT stateless (algoritma HS256) via cookie HTTP-Only.
    - Proteksi route berbasis Edge Middleware dengan pengalihan otomatis per role.
    - Otorisasi server-level (assertStoreAccess) pada setiap mutasi Server Actions.

7.2 POINT OF SALE (POS) KASIR & KERANJANG BELANJA
    - Pengurutan Cerdas Produk (Smart Sorting): Produk yang stoknya tersedia (stockQuantity > 0)
      selalu ditampilkan di posisi paling atas secara alfabetis (A–Z). Produk yang stoknya
      habis (stockQuantity = 0) otomatis diturunkan ke bawah (juga urut A–Z), mempermudah
      kasir memilih roti tanpa perlu mencari.
    - Keranjang belanja interaktif (Cart State) multi-item pada antarmuka kasir.
    - Penambahan, pengurangan jumlah, dan validasi stok fisik maksimum secara otomatis.
    - Modal Pembayaran Lengkap (PaymentModal):
      * Metode Bayar: Tunai (Cash), QRIS, dan Transfer Bank.
      * Kalkulator uang tunai dengan tombol nominal cepat (Uang Pas, 50rb, 100rb, dll).
      * Perhitungan otomatis uang kembalian dan deteksi uang kurang.
    - Pencatatan transaksi massal otomatis (recordBulkSales) dalam satu kali proses checkout
      dengan menyimpan nomor resi unik, metode bayar, uang diterima, dan kembalian ke database.

7.3 CETAK STRUK & VERIFIKASI KEASLIAN RESI (ANTI-FRAUD)
    - Pembuatan nomor resi unik otomatis berformat 'FB-YYYYMMDD-XXXX'.
    - Modal tampilan struk belanja thermal bergaya kasir asli (ReceiptModal).
    - Rincian nota: Nama cabang, lokasi, kasir, waktu transaksi, daftar item,
      harga satuan, diskon item, subtotal, total diskon, total akhir, metode bayar,
      nominal uang tunai yang diserahkan, dan nominal kembalian.
    - Tombol cetak langsung ke printer thermal (window.print()) dengan styling
      CSS khusus cetak (.print-container & .no-print).
    - Fitur Validasi / Cek Keaslian Struk (VerifyReceiptModal):
      * Tombol "Cek Struk" di antarmuka kasir untuk memverifikasi struk fisik yang dibawa pembeli.
      * Memeriksa nomor resi secara instan ke database untuk menampilkan catatan asli transaksi
        (waktu transaksi resmi, nama toko, kasir, rincian produk, dan nominal bayar).
      * Menampilkan badge hijau terverifikasi jika struk asli, atau peringatan merah jika palsu.

7.4 KATALOG MASTER PRODUK & PENYESUAIAN HARGA GLOBAL
    - Sentralisasi katalog menu di /products terpisah dari inventaris toko.
    - Tambah, edit, dan hapus master produk dengan proteksi integritas relasi.
    - Penyesuaian Harga Massal (Bulk Price Adjustment):
      * Menaikkan atau menurunkan seluruh harga produk secara serentak.
      * Pilihan penyesuaian berdasarkan Nominal Rupiah (Rp) atau Persentase (%).
      * Otomatis terintegrasi ke seluruh cabang secara instan.

7.5 NOTIFIKASI EMAIL STOK RENDAH OTOMATIS
    - Endpoint otomatis /api/notify-low-stock terintegrasi layanan Resend API.
    - Dilindungi token verifikasi CRON_SECRET dengan perbandingan konstan waktu
      (crypto.timingSafeEqual) untuk mencegah celah timing attack.
    - Generator template email HTML modern (lib/email-templates.ts) berisi tabel
      daftar produk kritis, sisa stok, dan nama cabang terkait.

7.6 PREDIKSI PENJUALAN BERBASIS AI (DEMAND FORECASTING)
    - Halaman analitik /forecast memanfaatkan TimesFM AI Engine.
    - Memproyeksikan estimasi kebutuhan penjualan produk 7 hari ke depan per cabang.
    - Membantu bagian produksi dapur menghindari kelebihan atau kekurangan produksi.
    - Visualisasi grafik deret waktu interaktif (ForecastChart) dengan filter toko.

7.7 DASHBOARD PERFORMA & ANALITIK EKSEKUTIF
    - 5 KPI Cards Real-Time:
      1. Total Omzet Penjualan (disertai persentase margin keuntungan)
      2. Total Transaksi Terverifikasi
      3. Jumlah Cabang Operasional Aktif
      4. Total Varian Menu Master Aktif
      5. Total Stok Fisik Gabungan Seluruh Cabang
    - Grafik Tren Penjualan 30 hari terakhir (Revenue vs Profit) berbasis Recharts.
    - Rincian Penjualan per Produk (Product Sales Breakdown) dengan filter cabang.
    - Revalidasi data otomatis (ISR 60 detik) untuk menjaga kesegaran data.

7.8 MANAJEMEN CABANG (STORES) & PENGGUNA
    - Tambah, ubah nama/lokasi, dan hapus cabang toko dengan modal konfirmasi.
    - Manajemen Staf Kasir/Manager per cabang: Admin dapat mendaftarkan akun staf
      khusus untuk toko bersangkutan langsung dari panel detail cabang.
    - Penugasan menu dari Master Katalog ke cabang dengan input stok awal.

7.9 RIWAYAT AKTIVITAS LENGKAP (AUDIT TRAIL)
    - Halaman khusus /audit untuk memantau segala aktivitas sistem.
    - Mencatat waktu kejadian, username pelaku, jenis aktivitas, nama objek data,
      cabang terkait, serta payload detail.
    - Fitur filter interaktif berdasarkan: Jenis Aksi, Cabang Toko, dan Rentang Waktu.
    - Sistem paginasi (50 entri per halaman) dan tombol pembersihan riwayat log.

7.10 PELAPORAN & EKSPOR EXCEL (.XLSX)
    - Ekspor data Penjualan dan Inventaris Stok terfilter.
    - Filter berdasarkan cabang dan periode (Hari Ini, 7 Hari, 30 Hari, Bulan Ini, Custom).
    - Tampilan ringkasan metrik dan preview 50 baris pertama data di layar.
    - Unduhan file Excel dengan header berbahasa Indonesia dan format mata uang Rupiah.

7.11 PENGALAMAN PENGGUNA (UI/UX)
    - Dukungan Dark Mode dan Light Mode penuh via next-themes.
    - Desain antarmuka responsif (Mobile, Tablet, Desktop) dengan custom scrollbar.
    - Komponen notifikasi popup interaktif menggunakan Sonner Toaster.

9. KELEBIHAN PROGRAM
================================================================================

1. ARSITEKTUR HYBRID CLOUD & EDGE MODERN
   Menggunakan Next.js 16 App Router, React 19 Server Components, dan Prisma ORM
   yang sangat cepat dan hemat resource.

2. SISTEM POS & CHECKOUT MULTI-ITEM LENGKAP
   Memiliki kasir terpadu dengan keranjang belanja, kalkulator uang kembalian,
   dukungan pembayaran non-tunai (QRIS & Transfer), serta cetak nota thermal instan.

3. KATALOG MASTER TERPUSAT & KONTROL HARGA GLOBAL
   Menjaga konsistensi nama dan varian produk di semua cabang, sekaligus
   memungkinkan penyesuaian harga massal se-Indonesia hanya dengan satu klik.

4. OTOMASI EARLY-WARNING STOK DENGAN EMAIL
   Tidak hanya mengandalkan banner di dashboard, tetapi juga mengirimkan
   email peringatan langsung ke pengelola toko sebelum stok benar-benar habis.

5. PENERAPAN KECERDASAN BUATAN (TIMESFM AI)
   Memberikan perkiraan peramalan produksi harian berbasis data historis,
   mengurangi pemborosan bahan baku (*food waste*) akibat roti basi tidak terjual.

6. JEJAK AUDIT TRANSPARAN & KEAMANAN BRUTE-FORCE
   Mencegah manipulasi internal dan serangan peretasan melalui pencatatan log
   komprehensif dan pembatasan frekuensi gagal login.

7. SISTEM ISOLASI PERAN (RBAC) KETAT
   Manager cabang hanya bisa melihat dan memproses data toko miliknya sendiri,
   mencegah kebocoran data antar cabang.

10. KEKURANGAN AKTUAL & AREA PENGEMBANGAN SOFTWARE LEBIH LANJUT
================================================================================

Berikut adalah analisis kekurangan aktual yang belum ada di dalam sistem
dan sangat disarankan untuk agenda pengembangan software ke tahap berikutnya:

--- PRIORITAS TINGGI (Operasional Kasir, Keuangan & Integritas Bisnis) ---

1. BELUM ADA MANAJEMEN BAHAN BAKU & HPP (COST OF GOODS SOLD / COGS)
   *Masalah:* Saat ini profit masih menggunakan estimasi persentase atau selisih
   sederhana. Belum ada pencatatan resep roti (misal: 1 Roti Cokelat membutuhkan
   50gr tepung, 10gr mentega, 15gr cokelat) dan pengurangan stok bahan baku otomatis.
   *Dampak:* Manajemen tidak mengetahui harga pokok produksi (HPP) sebenarnya,
   sehingga margin laba bersih tidak 100% akurat.

2. BELUM TERSEDIA MODE OFFLINE / PWA (PROGRESSIVE WEB APP)
   *Masalah:* Sistem sepenuhnya bergantung pada koneksi internet cloud Supabase.
   Jika jaringan internet di toko cabang terputus, kasir tidak dapat melayani transaksi.
   *Dampak:* Antrean kasir terhambat dan penjualan saat internet mati tidak tercatat.

3. BELUM ADA INTEGRASI PEMBAYARAN PAYMENT GATEWAY OTOMATIS
   *Masalah:* Metode QRIS dan Transfer Bank saat ini bersifat verifikasi manual
   oleh kasir (kasir melihat bukti transfer dan langsung menekan konfirmasi).
   *Dampak:* Berpotensi terjadi kelalaian atau pemalsuan struk transfer oleh pembeli
   karena belum ada Webhook callback otomatis dari gateway seperti Midtrans/Xendit.

4. BELUM ADA PENGUJIAN OTOMATIS (UNIT & E2E TESTING)
   *Masalah:* Belum ada test suite terkonfigurasi (Vitest, Jest, Playwright).
   *Dampak:* Pembaruan kode di masa mendatang berisiko memunculkan regresi atau bug
   pada kalkulasi finansial tanpa terdeteksi secara otomatis.

--- PRIORITAS MENENGAH (Efisiensi Kerja, Filter & Pengadaan) ---

5. BELUM ADA MANAJEMEN KATEGORI PRODUK
   *Masalah:* Seluruh produk berada dalam satu daftar flat tanpa pengelompokan
   kategori (misal: Roti Manis, Roti Tawar, Cake & Tart, Pastry/Croissant, Minuman).
   *Dampak:* Ketika varian produk mencapai puluhan hingga ratusan, staf kasir
   kesulitan melakukan filter selain mengetik kata kunci nama produk.

6. BELUM ADA MODUL PEMBELIAN & MANAJEMEN SUPPLIER (PROCUREMENT / PO)
   *Masalah:* Belum ada fitur untuk mencatat Purchase Order (PO) pembelian bahan,
   daftar kontak pemasok (supplier), riwayat hutang dagang, dan tanggal jatuh tempo.
   *Dampak:* Bagian pengadaan masih harus mencatat nota belanja pasar secara manual.

7. BELUM ADA SISTEM DISKON KHUSUS & PROMOSI DINAMIS (PROMO ENGINE)
   *Masalah:* Diskon yang didukung saat ini hanyalah potongan persentase statis per produk.
   Belum ada promo fleksibel seperti "Beli 2 Gratis 1", diskon jam tertentu (Happy Hour
   roti malam hari), atau kupon voucher.
   *Dampak:* Strategi promosi pemasaran toko belum dapat diotomatisasi oleh sistem.

8. BELUM TERINTEGRASI SCANNER BARCODE / QR FISIK
   *Masalah:* Input menu masih mengandalkan pencarian klik di layar.
   *Dampak:* Kasir sedikit lebih lambat saat menghadapi jam sibuk dibandingkan
   menggunakan barcode scanner genggam.

--- PRIORITAS RENDAH (Retensi Pelanggan & Laporan Finansial Lanjut) ---

9. BELUM ADA SISTEM CRM & LOYALITAS PELANGGAN (MEMBERSHIP)
   *Masalah:* Belum ada pencatatan data nomor HP/nama pelanggan, riwayat belanja
   member, dan pengumpulan poin reward belanja.
   *Dampak:* Sulit melakukan program retensi pelanggan setia.

10. BELUM ADA LAPORAN LABA RUGI LENGKAP & BIAYA OPERASIONAL (OPEX)
    *Masalah:* Laporan yang tersedia berfokus pada omzet penjualan dan stok produk.
    Belum ada input pencatatan biaya operasional toko (sewa tempat, listrik, gaji staf,
    kantong plastik) untuk menyajikan laporan Laba Rugi Bersih bulanan.

11. SPLIT BILL / MULTI-TENDER PAYMENT BELUM DIDUKUNG
    *Masalah:* Transaksi harus dibayar dengan satu jenis metode bayar (100% Tunai
    atau 100% QRIS). Belum bisa kombinasi (misal: Rp 20.000 tunai + Rp 30.000 QRIS).

FASE 1 (Jangka Pendek: 1 - 2 Bulan) — Stabilitas & Efisiensi Kasir:

  - Otomasi saran pembelian bahan baku ke supplier berdasarkan prediksi AI TimesFM.
  - Aplikasi Mobile Native untuk Kasir Tablet dan Owner Monitoring.

12. INFORMASI TEKNIS TAMBAHAN
================================================================================

Format Standar Sistem:
  - Mata Uang   : Rupiah Indonesia (IDR), format penulisan lokal 'id-ID'.
  - Zona Waktu  : Asia/Jakarta (WIB, UTC+7) pada seluruh tampilan audit dan resi.
  - Format Resi : FB-YYYYMMDD-XXXX (Unik per sesi transaksi kasir).

Standar Cetak Struk:
  - Target Perangkat : Printer Thermal Kasir ukuran lebar kertas 58mm / 80mm.
  - Font Struk       : Monospace font-mono dengan tabel ringkas bergaris putus-putus.

Algoritma Keamanan:
  - Password Hash    : bcryptjs (Salt rounds: 10).
  - Sesi Login       : JWT HS256 stateless dalam Cookie berpelindung HttpOnly & Secure.
  - Cron Endpoint    : Header otorisasi diverifikasi dengan crypto.timingSafeEqual.
  - Rate Limiter     : AuditLog check (Maks 5 kali gagal per 15 menit per username).
