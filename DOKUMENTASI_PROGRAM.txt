================================================================================
1. DESKRIPSI UMUM PROGRAM
================================================================================

Family Bakery - Sistem Manajemen Stok WEB adalah aplikasi web berbasis cloud yang
dirancang khusus untuk membantu usaha roti/bakery dalam mengelola stok produk,
mencatat penjualan, memantau performa cabang, serta menghasilkan laporan bisnis
secara digital.

Aplikasi ini ditargetkan untuk bisnis bakery yang memiliki satu atau lebih cabang
(multi-store), dengan sistem peran pengguna (Admin dan Manager) sehingga setiap
cabang bisa dioperasikan secara independen namun tetap terpantau dari satu
dashboard terpusat.

================================================================================
2. TUJUAN PROGRAM
================================================================================

- Menggantikan pencatatan manual (buku/kertas) dengan sistem digital berbasis web
- Memudahkan pengelolaan stok produk di setiap cabang toko
- Memantau penjualan harian, mingguan, dan bulanan secara real-time
- Menghasilkan laporan penjualan dan stok dalam format Excel (.xlsx)
- Memberikan peringatan otomatis ketika stok produk hampir habis
- Memungkinkan pengelolaan banyak cabang dari satu akun admin

4. ARSITEKTUR APLIKASI
================================================================================

Aplikasi menggunakan arsitektur Next.js App Router modern dengan:

  a) Server Components
     - Pengambilan data langsung dari database di sisi server
     - Efisiensi lebih tinggi (tidak perlu round-trip ke client)
     - ISR (Incremental Static Regeneration) dengan revalidate 60 detik

  b) Client Components
     - Form interaktif, modal, dropdown, chart interaktif
     - State management lokal (React useState / useMemo)

  c) Server Actions
     - Mutasi data (tambah, edit, hapus produk/toko/pengguna)
     - Login dan logout autentikasi

  d) API Routes
     - /api/auth     : Login endpoint
     - /api/export   : Export data penjualan dan stok
     - /api/upload   : Upload gambar produk ke Supabase Storage

6. MODEL DATABASE (SKEMA PRISMA)
================================================================================

Program ini menggunakan 5 tabel utama:

--- Model: User ---
  id           : String (ID unik, CUID)
  username     : String (unik)
  passwordHash : String (password terenkripsi bcrypt)
  name         : String (opsional, nama tampilan)
  role         : Enum [ADMIN | MANAGER]
  storeId      : String (opsional, cabang yang dikelola)
  createdAt    : DateTime

--- Model: Store (Cabang) ---
  id        : String (ID unik)
  name      : String (nama cabang)
  location  : String (opsional, lokasi/alamat)
  products  : Product[] (relasi ke produk)
  sales     : Sale[] (relasi ke penjualan)
  users     : User[] (relasi ke pengguna)
  createdAt : DateTime
  updatedAt : DateTime

--- Model: Product (Produk) ---
  id            : String (ID unik)
  storeId       : String (cabang pemilik produk)
  name          : String (nama produk)
  description   : String (opsional, deskripsi)
  imageUrl      : String (opsional, URL gambar)
  price         : Float (harga jual)
  discount      : Int (diskon %, default 0)
  stockQuantity : Int (jumlah stok, default 0)
  createdAt     : DateTime
  updatedAt     : DateTime

--- Model: Sale (Penjualan) ---
  id           : String (ID unik)
  storeId      : String (cabang transaksi)
  productId    : String (produk yang dijual)
  quantitySold : Int (jumlah unit terjual)
  totalAmount  : Float (total pendapatan)
  profitAmount : Float (total keuntungan)
  saleDate     : DateTime (tanggal & waktu transaksi)

--- Model: AuditLog (Riwayat Aktivitas) ---
  id         : String (ID unik)
  userId     : String (opsional, ID pengguna yang melakukan aksi)
  username   : String (opsional, username pelaku)
  action     : String (jenis aksi: CREATE, UPDATE, DELETE, LOGIN, dll)
  entityType : String (entitas terkait: PRODUCT, STORE, USER, AUTH)
  entityId   : String (opsional, ID entitas)
  entityName : String (opsional, nama entitas yang diubah)
  detail     : String (opsional, detail tambahan JSON/String)
  storeId    : String (opsional, cabang terkait aksi tersebut)
  createdAt  : DateTime (waktu kejadian)

Indeks database dioptimalkan pada:
  - storeId, productId, saleDate (query cepat)
  - userId, action, createdAt (query untuk audit log)
  - storeId + saleDate (kombinasi untuk laporan per cabang)
  - stockQuantity (untuk filter stok rendah)

7. FITUR-FITUR PROGRAM
================================================================================

7.1 AUTENTIKASI & KEAMANAN
    - Login dengan username + password
    - Terdapat fitur Show/Hide password untuk kemudahan input
    - Password dienkripsi menggunakan bcryptjs
    - Sesi berbasis JWT (HS256) yang disimpan di cookie HTTP-Only
    - Masa aktif sesi: 7 hari
    - Cookie aman (Secure) di mode produksi
    - Proteksi halaman: redirect ke /login jika belum login
    - Dua level akses: ADMIN dan MANAGER

7.2 SISTEM PERAN (ROLE-BASED ACCESS)
    - ADMIN:
        * Akses penuh ke semua fitur
        * Dapat melihat semua cabang
        * Dapat membuat, mengedit, dan menghapus cabang
        * Dapat mengelola semua produk di semua cabang
        * Dapat melihat laporan gabungan semua cabang
        * Dapat menambah/hapus pengguna Manager per cabang
    - MANAGER:
        * Akses terbatas ke cabang yang ditugaskan
        * Hanya melihat menu "Cabang Saya"
        * Dapat mengelola produk dan stok di cabangnya sendiri
        * Dapat mencatat penjualan di cabangnya

7.3 DASHBOARD UTAMA
    - KPI Cards (4 kartu statistik):
        * Total Cabang aktif
        * Total Produk (seluruh cabang)
        * Total Transaksi (semua waktu)
        * Total Omzet (dalam Rupiah, format disingkat: jt = juta)
    - Grafik Penjualan (Recharts):
        * Data 30 hari terakhir
        * Visualisasi Revenue & Profit
        * Filter per cabang
    - Breakdown Penjualan per Produk
    - Skeleton loading saat data sedang dimuat
    - Revalidasi data otomatis setiap 60 detik (ISR)

7.4 MANAJEMEN CABANG (STORES)
    - Lihat daftar semua cabang toko
    - Tambah cabang baru (nama + lokasi)
    - Edit informasi cabang
    - Hapus cabang (dengan konfirmasi)
    - Cascade delete: hapus cabang akan menghapus semua produk & penjualannya
    - Kelola pengguna Manager per cabang

7.5 MANAJEMEN PRODUK
    - Lihat daftar produk per cabang
    - Tambah produk baru:
        * Nama produk
        * Deskripsi (opsional)
        * Upload gambar (ke Supabase Storage)
        * Harga jual
        * Diskon (%)
        * Stok awal
    - Edit produk (semua field)
    - Hapus produk
    - Pencarian produk (real-time)
    - Tampilan kartu produk dengan gambar, harga, stok, dan badge diskon

7.6 PENCATATAN PENJUALAN & RESTOCK
    - Catat penjualan produk (jumlah unit terjual)
    - Stok otomatis berkurang saat penjualan dicatat
    - Tambah stok (restock) produk
    - Perhitungan otomatis: total amount & profit amount

7.7 PERINGATAN STOK RENDAH (LOW STOCK ALERT)
    - Deteksi otomatis produk dengan stok menipis
    - Badge/indikator visual pada kartu produk
    - Alert khusus untuk produk yang hampir habis
    - Status stok: "Tersedia", "Hampir Habis", "Habis"

7.8 LAPORAN & EKSPOR DATA
    - Filter data berdasarkan:
        * Jenis data: Penjualan atau Stok Produk
        * Cabang: semua atau cabang tertentu
        * Rentang waktu: Hari Ini, 7 Hari, 30 Hari, Bulan Ini, Custom
    - Preview data sebelum diunduh (tampilan 50 baris pertama)
    - Ringkasan: Total Transaksi, Total Unit, Total Omzet
    - Download laporan ke Excel (.xlsx) dengan:
        * Header kolom dalam Bahasa Indonesia
        * Auto-width kolom
        * Format mata uang Rupiah
    - Format file laporan penjualan:
        No | Tanggal | Cabang | Produk | Jumlah | Harga Satuan | Total
    - Format file laporan stok:
        No | Cabang | Produk | Harga | Stok Saat Ini | Status

7.9 AUDIT LOG (RIWAYAT AKTIVITAS)
    - Pencatatan otomatis setiap aksi penting yang dilakukan oleh pengguna
    - Melacak siapa (user), apa (aksi), dan kapan (waktu)
    - Menyimpan log untuk login, tambah/edit/hapus produk, cabang, dan user
    - Halaman khusus Audit untuk memantau seluruh riwayat aktivitas

7.10 DARK MODE / LIGHT MODE
    - Toggle tema terang/gelap
    - Preferensi tema tersimpan (next-themes)
    - Semua komponen mendukung dark mode
    - Transisi warna halus

7.11 RESPONSIVE DESIGN
    - Layout adaptif untuk desktop, tablet, dan mobile
    - Sidebar dapat disembunyikan (mobile hamburger menu)
    - Grid responsif (2 kolom mobile → 4 kolom desktop)
    - Tabel dengan horizontal scroll pada layar kecil

8. CARA MENJALANKAN PROGRAM (SETUP & INSTALASI)
================================================================================

PRASYARAT:
  - Node.js versi 18 atau lebih baru
  - npm (Node Package Manager)
  - Akun Supabase (database PostgreSQL)
  - Akun Vercel (untuk deployment)

LANGKAH INSTALASI LOKAL:

  1. Clone repository:
     git clone https://github.com/Ferdyagustian/Family-Bakery-Stok-WEB.git
     cd Family-Bakery-Stok-WEB

  2. Install dependensi:
     npm install

  3. Buat file .env dan isi variabel berikut:
     DATABASE_URL="postgresql://..."
     JWT_SECRET="kunci-rahasia-anda"
     NEXT_PUBLIC_SUPABASE_URL="https://xxx.supabase.co"
     NEXT_PUBLIC_SUPABASE_ANON_KEY="eyJ..."
     SUPABASE_SERVICE_ROLE_KEY="eyJ..."

  4. Jalankan migrasi database:
     npx prisma db push

  5. (Opsional) Buat akun admin awal:
     node scripts/...

  6. Jalankan server pengembangan:
     npm run dev

  7. Buka browser di: http://localhost:3000

SKRIP NPM YANG TERSEDIA:
  npm run dev        <- Server pengembangan (hot reload)
  npm run build      <- Build produksi
  npm run start      <- Jalankan build produksi
  npm run lint       <- Cek kualitas kode (ESLint)

DEPLOYMENT KE VERCEL:
  - Hubungkan repository GitHub ke Vercel
  - Tambahkan environment variables di dashboard Vercel
  - Deploy otomatis setiap ada push ke branch utama

10. KEKURANGAN PROGRAM
================================================================================

--- TINGKAT: KRITIS (Berdampak pada Operasional Inti & Keamanan Data) ---

1. BELUM ADA FITUR BACKUP DATA MANUAL
   Pengguna tidak dapat melakukan backup/export database secara mandiri dari dalam aplikasi. Backup bergantung sepenuhnya pada Supabase.
   *Alasan Kritis:* Risiko kehilangan data fatal jika terjadi kesalahan (human error) atau isu pada cloud server, yang dapat menghentikan seluruh operasional bisnis.

2. TIDAK ADA FITUR OFFLINE
   Aplikasi sepenuhnya bergantung pada koneksi internet dan server cloud (Supabase + Vercel). Jika internet mati, aplikasi tidak dapat digunakan.
   *Alasan Kritis:* Toko retail/bakery harus terus melayani pelanggan. Jika internet terputus, kasir tidak bisa mencatat penjualan sehingga antrean menumpuk dan pendapatan tidak tercatat secara real-time.

3. SKALABILITAS DATABASE TERBATAS (FREE TIER)
   Jika menggunakan Supabase free tier, ada batasan koneksi dan penyimpanan.
   *Alasan Kritis:* Jika batas koneksi penuh saat jam sibuk, aplikasi akan down atau gagal memuat/menyimpan data, yang melumpuhkan operasional seluruh cabang.

4. BELUM ADA PENGUJIAN OTOMATIS (UNIT / INTEGRATION TEST)
   Tidak ditemukan file test (Jest, Playwright, Cypress) dalam proyek.
   *Alasan Kritis:* Risiko tinggi munculnya bug tersembunyi yang merusak data produksi saat tim melakukan pembaruan fitur, terutama untuk proses hitung-hitungan finansial.

--- TINGKAT: MENENGAH (Berdampak pada Efisiensi Kerja & Perhitungan Bisnis) ---

5. LAPORAN TERBATAS
   Saat ini laporan hanya mencakup penjualan dan stok. Belum ada laporan Laba Rugi bulanan, pembelian bahan baku (HPP), dan analisis produk terlaris.
   *Alasan Menengah:* Manajemen kesulitan menghitung profit bersih dan membuat keputusan strategis secara akurat, meski operasional harian tetap bisa berjalan.

6. TIDAK ADA FITUR POINT OF SALE (POS) LENGKAP
   Tidak ada keranjang belanja multi-produk dalam satu transaksi; setiap penjualan dicatat per produk.
   *Alasan Menengah:* Memperlambat proses pelayanan pelanggan saat pelanggan membeli berbagai jenis roti sekaligus dalam satu struk.

7. TIDAK ADA MANAJEMEN SUPPLIER / PEMBELIAN
   Tidak ada fitur untuk mencatat pembelian bahan baku, data supplier, atau perhitungan HPP.
   *Alasan Menengah:* Penghitungan stok dan biaya produksi dilakukan secara terpisah di luar sistem, meningkatkan beban kerja manual admin.

8. TIDAK ADA MANAJEMEN KATEGORI PRODUK
   Produk tidak dapat dikategorikan (misalnya: Roti Manis, Roti Tawar, Kue), sehingga sulit difilter saat daftar produk sudah banyak.
   *Alasan Menengah:* Mempersulit pencarian dan analisis produk saat varian roti yang dijual mencapai ratusan macam.

--- TINGKAT: RENDAH (Fitur Tambahan, UX, dan Peningkatan Estetika) ---

9. TIDAK ADA FITUR BARCODE / QR CODE
   Pencatatan penjualan dan stok masih dilakukan secara manual melalui form tanpa integrasi scanner.
   *Alasan Rendah:* Pengguna masih bisa mengetikkan nama produk di kolom pencarian (search list), meski kurang efisien dibandingkan scanning.

10. TIDAK ADA NOTIFIKASI REAL-TIME (PUSH/EMAIL)
    Peringatan stok rendah hanya tampil di dashboard saat dibuka. Tidak ada notifikasi otomatis ke pengelola.
    *Alasan Rendah:* Manajer toko umumnya membuka dashboard setiap hari, sehingga status peringatan tetap akan terlihat secara proaktif.

11. TAMPILAN LAPORAN HANYA DI EXCEL
    Belum ada fitur cetak laporan ke PDF langsung dari aplikasi.
    *Alasan Rendah:* Laporan Excel (.xlsx) justru lebih disukai oleh akuntan untuk diolah kembali datanya. Ekspor PDF hanya untuk estetika formal.

12. TIDAK ADA FITUR CUSTOMER MANAGEMENT (CRM)
    Tidak ada pencatatan data pelanggan, program loyalitas, atau riwayat pembelian per pelanggan.
    *Alasan Rendah:* Rata-rata toko roti melayani pembeli anonim (walk-in) dan belum terlalu mendesak untuk memiliki sistem membership.

13. BELUM ADA FITUR MULTI-MATA UANG
    Program hanya mendukung mata uang Rupiah (IDR).
    *Alasan Rendah:* Target pasar dari Family Bakery adalah bisnis lokal di Indonesia, jadi ekspansi internasional (multi-currency) belum dibutuhkan.

12. INFORMASI TEKNIS TAMBAHAN
================================================================================

Algoritma Keamanan:
  - Password: bcryptjs (salt rounds: 10 atau lebih)
  - JWT Algorithm: HS256 (HMAC SHA-256)
  - Cookie: HTTP-Only, SameSite: Lax, Secure (production)

Batasan Data Dashboard:
  - Grafik menampilkan data 30 hari terakhir
  - Maksimal 1.000 data penjualan per query grafik
  - Preview ekspor menampilkan 50 baris pertama

Format Angka:
  - Mata uang: Rupiah (IDR) format id-ID
  - Zona waktu: Asia/Jakarta (WIB, UTC+7)
